# Technical debt

우선순위는 사용자 영향, 데이터 정확성, 운영 위험, 이후 작업을 막는 정도로
판단한다. 항목을 해결할 때 관련 자동 검증을 추가하고 이 목록에서 제거한다.

## High

- 수집 스케줄 실행 방식을 결정하고 실제 프로세스 진입점에 연결한다.
- Collector `/collect`, `/tag` 제어 API에 배포 환경용 인증 또는 네트워크 경계를
  추가한다.
- 요약 생성에 사용할 입력, 모델, 저장 상태, 실패 재시도 정책을 설계한다.

## Medium

- Collector 상태 갱신과 전송 실패 경로의 테스트 범위를 확장한다.
- `collector/src/config/sources.js`와 DB의 출처 초기 데이터가 어긋나지 않도록
  단일 원본 또는 동기화 검사를 도입한다.
- Collector README를 분리된 수집/태깅 흐름과 현재 소스 상태에 맞춘다.
- 서버의 페이지 크기와 태깅 batch 크기에 상한을 둔다.
- 태그 생성의 정규화 규칙과 LLM 응답 계약을 자동 검증한다.

## Later

- 수집 성공률, 지연, 실패 원인을 구조화된 로그와 지표로 관찰한다.
- 프런트엔드의 로딩, 빈 목록, 오류 및 핵심 사용자 흐름 테스트를 추가한다.
- 배포 플랫폼 선택 후 컨테이너 이미지, 상태 확인, 마이그레이션 및 롤백 절차를
  추가한다.
