# Technical debt

우선순위는 사용자 영향, 데이터 정확성, 운영 위험, 이후 작업을 막는 정도로
판단한다. 항목을 해결할 때 관련 자동 검증을 추가하고 이 목록에서 제거한다.

## High

- 기본 중지된 Collector CronJob을 자동화하기 전에 실행 주기, Groq 비용과 부분
  실패 시 재실행 정책을 검증한다.
- 상시 운영 전에 지원이 종료된 Kubernetes 1.31 클러스터를 지원 버전으로
  순차 업그레이드한다.
- local PersistentVolume의 PostgreSQL 데이터를 클러스터 밖에 백업하고 실제 복원
  절차를 검증한다.

## Medium

- 활성 출처인 우아한형제들 기술 블로그의 RSS 403과 쏘카 기술 블로그의 RSS 404를
  해결할 대체 피드를 확인하고, 유효한 피드가 없으면 복구 전까지 비활성화한다.
- Collector 상태 갱신과 전송 실패 경로의 테스트 범위를 확장한다.
- `collector/src/config/sources.js`와 DB의 출처 초기 데이터가 어긋나지 않도록
  단일 원본 또는 동기화 검사를 도입한다.
- 서버의 기사 조회 페이지 크기에 상한을 둔다.
- 의미가 겹치는 canonical 태그를 정리하고 별칭 목록을 실제 기사와 함께 지속적으로
  보강한다.
- RSS 설명이 없거나 지나치게 짧은 기사를 태깅 전에 구분하고 원문 메타데이터를
  제한적으로 보강하는 정책을 마련한다.
- 제목과 설명만으로 충분하지 않은 기사를 구분하고, 출처 정책을 지키면서 원문 본문을
  제한적으로 수집해 요약 근거를 보강한다.
- 실제 기사 고정 fixture로 AI 요약의 사실성, 언어, 길이 품질을 평가하는 절차를
  추가한다.

## Later

- 수집 성공률, 지연, 실패 원인을 구조화된 로그와 지표로 관찰한다.
- 프런트엔드의 로딩, 빈 목록, 오류 및 핵심 사용자 흐름 테스트를 추가한다.
- 단일 노드 local PersistentVolume을 동적 프로비저닝과 노드 장애 복구가 가능한
  스토리지 또는 외부 관리형 PostgreSQL로 교체한다.
